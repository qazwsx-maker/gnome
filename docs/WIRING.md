# ต่อสาย Scout — earth กับ sky

ผังขาตรงกับแคตตาล็อกใน firmware 0.6.0 (`firmware/src/sensors.cpp`) ติ๊กเลือกเซ็นเซอร์ได้ที่หน้า
`http://<ip>/` ของแต่ละ node โดยไม่ต้องกรอกเลขขาเอง

## กฎที่ใช้กับทั้งสองตัว

- **ไฟเลี้ยงเซ็นเซอร์เป็น 3.3V เสมอ ห้าม 5V** โมดูล analog ที่เลี้ยงด้วย 5V จะส่งแรงดันเกิน 3.3V
  เข้าขา ADC แล้วพัง
- **ขา analog ต้องเป็น ADC1 เท่านั้น** (D32 D33 D34 D35 VP VN) ขาอื่นเป็น ADC2 ซึ่งอ่านไม่ได้เลย
  ขณะเปิด WiFi — firmware จะปฏิเสธถ้าตั้งผิดขา
- **ขา DO ของโมดูล analog ไม่ต้องต่อ** เราใช้ค่าต่อเนื่องจาก AO ไม่ใช่สัญญาณเปิด/ปิด
- **VCC ของโมดูล analog ต่อเข้า D13 ไม่ใช่ 3V3** firmware จ่ายไฟเฉพาะ 150 มิลลิวินาทีตอนอ่าน
  แล้วตัด หัววัดแบบ resistive กร่อนจากไฟที่ค้างอยู่ตลอดเวลา ไม่ใช่จากน้ำ
- ขั้วสกรูมีรูเดียวต่อขา ขาที่ต้องแยกไปหลายตัว (3V3, GND, D13, D21, D22) ให้พักผ่าน
  **ขั้วต่อสายไฟ** ที่ซื้อไว้ (6 ช่อง 1 ตัว, 2 ช่อง 5 ตัว) อย่าพันสายยัดรูเดียวถ้าเลี่ยงได้

## earth — อากาศ + ดิน

ของเดิม: AM2301A และจอ OLED · ของใหม่: หัววัดดิน 2 ตัว

| อุปกรณ์ | สาย | เข้าขั้ว |
|---|---|---|
| AM2301A | แดง (VCC) | **D25** (ตั้ง `dht_power_pin` = 25) · เดิม 3V3 |
| | เหลือง (DATA) | **D4** |
| | ดำ (GND) | GND |
| จอ OLED | VCC | 3V3 |
| | GND | GND |
| | SCL | **D22** |
| | SDA | **D21** |
| หัววัดดิน #1 | AO | **D34** |
| | VCC | **D13** |
| | GND | GND |
| หัววัดดิน #2 | AO | **D35** |
| | VCC | **D13** |
| | GND | GND |

**ยังค้างอยู่:** ใส่ตัวต้านทาน **4.7–10 kΩ คร่อมระหว่าง D4 กับ 3V3** นี่คือสาเหตุที่ค่าจาก
AM2301A หลุดเป็นช่วงๆ มาตลอด สายยาวแบบนี้ต้องมี

**ทำไมสายแดงไป D25:** AM2301A ค้างในคืนที่ความชื้นเกิน ~80% (25 ต.ค. 22:30, 27 ต.ค. 21:17) อ่านได้แต่ค่าว่าง
และรีบูตบอร์ดก็ไม่หาย ต้องตัดไฟตัวเซ็นเซอร์เท่านั้น เมื่อเลี้ยงไฟจาก D25 firmware (0.8.16+) จะตัดไฟ 3 วิ แล้วจ่ายใหม่เอง
เมื่ออ่านไม่ได้ 3 รอบติด (เว้นอย่างน้อย 5 นาทีระหว่างรอบ) · เห็นใน event `dht_reset` / `dht_ok`
ตัวต้านทาน pull-up คร่อม D4–3V3 คงไว้ได้ (ตอนตัดไฟ firmware ดึง D4 ลง LOW ให้ด้วย)

ปักหัววัดในกระถางคนละใบ ให้ลึกพอที่แผ่นโลหะจมดินทั้งแผ่น อย่าให้โดนก้นกระถาง

## sky — แสง + ฝน

ของเดิม: โดม BH1750 · ของใหม่: ฐานรอง terminal, แผ่นวัดน้ำฝน, จอ OLED

| อุปกรณ์ | สาย | เข้าขั้ว |
|---|---|---|
| โดม BH1750 | 1 VCC | 3V3 |
| | 2 SCL | **D22** |
| | 3 DAT | **D21** |
| | 4 GND | GND |
| | 5 ADDR | ปล่อยลอย |
| จอ OLED | VCC | 3V3 |
| | GND | GND |
| | SCL | **D22** |
| | SDA | **D21** |
| แผ่นวัดน้ำฝน | AO | **D33** |
| | VCC | **D13** |
| | GND | GND |

โดมกับจออยู่บนสาย I2C เส้นเดียวกันได้ เพราะคนละแอดเดรส (โดม 0x23 · จอ 0x3C) ต้องพัก D21
กับ D22 ผ่านขั้วต่อสายไฟเพื่อแยกไปสองทาง

**ติดแผ่นรับน้ำให้เอียงอย่างน้อย 30°** ถ้าวางราบน้ำจะขังบนแผ่นแล้วค่าค้างว่าฝนตกทั้งที่หยุดไปแล้ว

## หลังต่อเสร็จ

1. เสียบไฟ รอ node ขึ้นออนไลน์บน Hut
2. เปิด `http://<ip>/` ของ node แล้วติ๊กเซ็นเซอร์ที่ต่อจริง
   - earth: AM2301A, หัววัดดิน #1, หัววัดดิน #2
   - sky: แผ่นวัดน้ำฝน
   - จอกับโดมไม่ต้องติ๊ก ระบบสแกน I2C เจอเอง
3. กดบันทึก node จะรีบูตแล้วเริ่มส่งค่า
4. **ปรับเทียบหัววัด** ค่าเริ่มต้นเป็นของหัว capacitive คนละสเกลกับหัว resistive ที่เรามี
   ถ้าไม่ปรับ เปอร์เซ็นต์จะเพี้ยน วิธีคืออ่านค่า raw ตอนหัวแห้งในอากาศ แล้วอ่านอีกครั้ง
   ตอนปักในกระถางที่เพิ่งรดน้ำ เอาสองค่านั้นไปใส่ช่อง dry/wet ในหัวข้อ "ขั้นสูง"

## เช็กว่าต่อติดไหม

- จอติด = I2C ใช้ได้
- บน Hut เห็นค่า `lux` (sky) และ `dht_temp_c`/`dht_rh_pct` (earth) = เซ็นเซอร์นั้นมาแล้ว
- เห็น `soil1_pct`, `soil2_pct`, `rain_pct` = ช่อง analog มาแล้ว
- เจอตัวเดียวจากสองตัวบนบัส I2C มักเป็นสายไม่แน่น ไม่ใช่โมดูลเสีย

## Watcher — ขาตั้ง pan-tilt (SG90 ×2) ต่อกับ ESP32-CAM

ตัวล่าง (ฐาน) = **pan หัน** · ตัวบน (ถือกล้อง) = **tilt ก้มเงย** · firmware ≥ 0.7.0

> ⚠️ **ต้องเป็น SG90 แบบกำหนดมุม 180° ทั้งสองตัว ห้ามใช้รุ่น 360° (continuous rotation)**
> ชุดขาตั้งบางเจ้าแถม SG90 360° มาด้วย หน้าตาเหมือนกันทุกอย่าง · เช็คง่ายๆ: ถอดไฟแล้วหมุนแกนด้วยมือ ถ้าหมุนได้รอบตัวไม่มีตัวหยุด = รุ่น 360°
> รุ่น 360° ตีความพัลส์เป็นความเร็ว ไม่ใช่มุม → สั่ง 100° = หมุนรอบตัวแรงๆ, จำหน้าตรงไม่ได้, สายพัน (เจอจริง 2026-10-23 ต้องปิด pan ไว้)
> firmware จำกัดความเร็วที่ 30°/วิ (ค่าเริ่ม 10) และปล่อยสัญญาณ 0.8 วิหลังหมุนถึง — ใช้ได้กับ servo 180° เท่านั้น
>
> **ถ้าตัวล่างเป็น 360° อยู่แล้ว** (firmware ≥ 0.8.0): dashboard → การ์ดกล้อง → ⚙ ตั้งค่า servo → ตัวล่าง "360°"
> ปุ่ม ◀ ▶ = หมุนช้าๆ 1 ก้าว (พัลส์ จุดหยุด ± แรงหมุน นาน "ต่อก้าว") แล้วปล่อยสัญญาณให้หยุด · นับก้าวจากหน้าตรง (ประมาณการ)
> เพดาน ±N ก้าวกันสายพัน · 🏠 หน้าตรง = ย้อนก้าวกลับ (คลาดได้) · servo คืบเองตอนไม่ได้กด → เลื่อน "จุดหยุด"
> MQTT: `cmd/servo {"pan_mode":"continuous","cont_us":70,"cont_ms":80,"stop_us":1500,"cont_limit":20}` · `cmd/pan +1`
> ผลจริงกับ SG90 360° (2026-10-24): ช่วงตาย ±25–30 µs แล้วกระโดดไปหมุนเร็วทันที → ก้าวละเอียดไม่ได้ · เปลี่ยนเป็น **MG90S** (180° เฟืองโลหะ) ทั้งสองตัวแทน
>
> **ชุดที่ใช้งานจริงตอนนี้**: MG90S ×2 · pan = **IO14** (ตัวล่าง) · tilt = **IO15** (ตัวบน) ตรงตามตาราง · ถ้ากดหันแล้วตัวบนขยับ = หัวเสียบ servo สลับ แก้ในซอฟต์แวร์ได้ด้วย `cmd/config {"servo_pin":15,"tilt_pin":14}` ไม่ต้องบัดกรีใหม่
> ตั้งค่า: หน้าตรง 90°/90° · ขอบเขต 10–170° ทั้งสองแกน · 10°/วิ · ◀ ▶ ▼ ▲ ทีละ 1°

| สาย servo | pan (ฐาน) | tilt (บน) | หมายเหตุ |
|---|---|---|---|
| ส้ม (signal) | **GPIO 14** | **GPIO 15** | ขา SD ที่ว่าง (13 ใช้แทนได้) · **ห้าม 12** (strapping pin: ถ้า servo ดึง high ตอนบูต บอร์ดไม่บูต) · ห้าม 4 (ไฟแฟลช) 0/1/3 |
| แดง (5V) | 5V | 5V | ดูเรื่องไฟข้างล่าง — **ห้ามใช้ 3.3V** |
| น้ำตาล (GND) | GND | GND | ต้องเป็น GND เดียวกับบอร์ดเสมอ |

### ไฟจากบอร์ดพอไหม

| ตัวกิน | ปกติ | พีค |
|---|---|---|
| ESP32-CAM (WiFi ส่ง + กล้อง) | 0.2–0.3 A | 0.5–0.6 A (บูต / init กล้อง / ส่งภาพ) |
| SG90 ตอนหมุน (ต่อตัว) | 0.2–0.3 A | 0.6–0.7 A ตอนออกตัว/ติดขัด |
| SG90 ตอนนิ่ง | ≈ 0 | firmware ปล่อยสัญญาณหลังหมุนถึง 1.2 วิ → ไม่ล็อกตำแหน่ง ไม่กินไฟ ไม่สั่น |

- firmware **ขยับทีละแกน** (หันก่อน รอ แล้วค่อยก้มเงย) → พีครวม ≈ 0.6 + 0.7 ≈ **1.3 A** ชั่วขณะ ถ้าขยับพร้อมกันจะถึง ~2 A
- ขา **5V ของ ESP32-CAM ต่อตรงกับไฟเข้า** (ไม่ผ่าน regulator — AMS1117 ทำแค่ 3.3V) ดึงจากขานี้ได้ แต่กระแสทั้งหมดต้องวิ่งผ่านสาย USB + บอร์ด MB (CH340) + ลายทองแดงบางๆ → แรงดันตกตอน servo ออกตัว → ESP32 brownout **รีบูตระหว่างหัน**
- **ทำแบบนี้**: 
  1. แยกสายแดงของ servo ไปรับ 5V **จากอะแดปเตอร์โดยตรง** (ตัดสาย USB อีกเส้นเอา 5V/GND หรือใช้ขั้วสกรู) ให้บอร์ดกับ servo ขนานกันที่อะแดปเตอร์ ไม่ใช่ servo ห้อยท้ายบอร์ด · GND รวมกัน
  2. ใส่ **คาปาซิเตอร์ 470–1000 µF / ≥ 6.3V** คร่อม 5V–GND ใกล้ servo (ขั้วลบด้าน GND) ดูดพีคตอนออกตัว
  3. อะแดปเตอร์ 5V 2A สองช่องที่ตัดสินใจไว้ (Mini Scout + Watcher): ให้ Watcher + servo อยู่ช่องของตัวเอง — Mini Scout ~0.2 A อยู่อีกช่อง ยังเหลือพอ · ถ้าจะหันบ่อย (patrol หลาย preset) ใช้อะแดปเตอร์ 5V 2A แยกให้ Watcher ไปเลยสบายกว่า
- อาการถ้าไฟไม่พอ: หันแล้วบอร์ดรีบูต / ภาพล่าสุดเป็นขาวโพลน / WiFi หลุดทุกครั้งที่หัน → ทำข้อ 1–2

### ตั้งค่าที่หน้าเว็บของ node (`http://esp32cam.local/`)
- servo pin = `14`, tilt pin = `15` → บันทึกและรีบูต
- ลองลาก slider "มุมก้มเงย" ดูว่ากล้องชนขาตั้งที่มุมไหน แล้วตั้ง **ก้มเงยต่ำสุด/สูงสุด** กันไว้ (ค่าปกติของขาตั้งแบบนี้ประมาณ 30–150)
- ทิศผิด (ลากซ้ายแล้วหันขวา / ก้มแล้วเงย) → ติ๊ก "กลับทิศ"
- preset มีช่อง "ก้มเงย" เพิ่ม: ใส่ค่าให้แต่ละมุม (ว่าง = ใช้มุมก้มเงยปัจจุบัน) · dashboard ส่ง `cmd/pan <preset>` แล้ว node ขยับทั้งสองแกนเอง
